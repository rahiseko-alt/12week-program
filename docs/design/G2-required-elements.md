## 1. 各回が満たすべき必須要素（全7項目）

| # | 要素 | 満たしているとみなす条件 |
|---|---|---|
| 1 | 回番号 | 1から始まる連番で、欠番・重複が無い |
| 2 | **見出し** | その回で扱うテーマを表す15文字以上の文字列。**Q3 の測定対象はこの欄**である |
| 3 | 実施日 | 具体的な日付（YYYY-MM-DD）が入っている |
| 4 | 目的 | 20文字以上の文で、その回で何をするかが書かれている |
| 5 | 到達点 | 20文字以上の文で、終わりに何ができていれば合格かが書かれている |
| 6 | 所要時間 | 分単位の数値が入っている |
| 7 | 次回までの宿題 | 文字列が入っている（宿題が無い回は「なし」と明記されている） |

## 2. 正規化の規則（回どうしを比べる前に行う変換）

同じ計画の中で「回ごとに中身が違うか」を見るとき、素の文字列で比べると、通し番号を付け替えただけの
雛形が「違う」と判定されてしまう。そこで比較の前に通し番号と日付だけを取り除く。

**入力語（会社名・業種・課題）は削除しない。** 同じ計画の中では全ての回が同じ入力語を共有するため、
削除は「別物を同一に潰す」方向にしか働かず、課題を複数書いた顧客向けの正しい計画を落とす
（basis-reviewer 5回目 反証3で実測）。

### 規則A：日付を削除

正規表現 `[0-9]{4}[-/年][0-9]{1,2}[-/月][0-9]{1,2}日?` に一致する箇所を削除する。**先に適用する。**

### 規則B：通し番号のかたまりを1つだけ剥がす

**文字列の先頭または末尾**にある通し番号のかたまりを、**1つだけ**取り除く。
文の途中には一切手を触れない。

**自己完結型の番号**（それ自体が番号記号であるもの）は、先頭・末尾にあればそのまま剥がす。

| 種類 | 例 |
|---|---|
| 丸数字 | `①` 〜 `⑳` |
| 括弧付き番号・英字 | `(1)` `（1）` `(A)` `（Ａ）` |
| 全角ローマ数字 | `Ⅰ` 〜 `Ⅻ` |

**裸の番号**（算用数字1〜2桁・全角数字1〜2桁・漢数字）は、次のいずれかを伴うときだけ剥がす。

- 前に `第` または `その` がある（例：`第3回` `第一回` `その2`）
- 後ろに `回` `回目` `章` `節` がある（例：`3回目`）
- 直後（先頭型）または直前（末尾型）に区切り記号がある（`：` `:` `、` `。` `．` `.` `)` `）` 半角/全角スペース）

剥がすかたまりには、付随する `第` `その` `回` `回目` `章` `節` と、隣接する区切り記号1個を含める。

**算用数字が3桁以上連続する場合は番号とみなさない**（年・金額・件数と紛れるため）。
**半角ラテン文字は `A.` のように区切り記号を伴う先頭型のときだけ**番号とみなす
（`AI` `IT` `KPI` の頭文字を番号と誤認しないため）。

この規則で落ちるもの・落ちないものは次のとおり（basis-reviewer 6回目 反証O-1・O-2 の実測ケース）。

| 入力 | 結果 | 判定 |
|---|---|---|
| `第1回：現状把握` / `第2回：現状把握` | どちらも `現状把握` | **同一＝落ちる**（正しい） |
| `①現状把握` / `②現状把握` | どちらも `現状把握` | **同一＝落ちる**（正しい） |
| `第一回現状把握` / `第二回現状把握` | どちらも `現状把握` | **同一＝落ちる**（正しい） |
| `現状把握 1` / `現状把握 2`（末尾） | どちらも `現状把握` | **同一＝落ちる**（正しい） |
| `現状把握その1` / `現状把握その2` | どちらも `現状把握` | **同一＝落ちる**（正しい） |
| `不良率を5%改善し、担当を割り付ける` / `不良率を10%改善し、担当を割り付ける` | 変換されない | **別物＝残る**（正しい） |
| `3か月後の目標値を共有する` | 変換されない | **別物＝残る**（正しい） |
| `AIによる検査の候補を洗い出す` | 変換されない | **別物＝残る**（正しい） |

### 骨格

規則A・規則Bを適用したのち、残った文字列から空白を除いたものを、その欄の **骨格** と呼ぶ。

## 4. 課題が違えば中身が変わること（Q3が参照）

### 4-1. 測り方＝削除ではなく「出現」を見る

**2つの計画の骨格が違うかどうかでは測らない。** その方式は向きが逆で、
課題の言葉を素直に使い分けた良い実装ほど、使い分けた部分が削除されて同一化し不合格になり、
逆に入力を1文字も読まない固定テンプレートが「偶然の削除差」で合格する
（basis-reviewer 6回目 反証O-3・O-4：忠実な実装が相違4/12で不合格、完全固定テンプレが20回中18回合格）。

そこで、**各計画が自分の課題の語を含み、相手の課題の語を含まないか**を見る。

### 4-2. 手続き

1. 質的に異なる2つの課題 A・B を選ぶ（4-4 の条件を満たすこと）。
2. それぞれで計画を作る（他の入力項目は 4-4 の条件どおりに揃える）。
3. **固有語**を決める。課題Aの固有語＝課題Aの本文に現れ、課題Bの本文には現れない語を3つ。
   課題Bの固有語も同様に3つ。いずれも2文字以上の名詞句とする。
4. 各計画の**全ての回の見出しを連結した文字列**について、次を確かめる。

| # | 確かめること | 落ちる実装 |
|---|---|---|
| 1 | 計画Aに、課題Aの固有語が**1つ以上出現する** | 入力を読まない固定テンプレート／ハッシュで固定プールを回す実装 |
| 2 | 計画Aに、課題Bの固有語が**1つも出現しない** | 課題を無視して両方の話を混ぜる実装 |
| 3 | 計画Bに、課題Bの固有語が**1つ以上出現する** | 同上 |
| 4 | 計画Bに、課題Aの固有語が**1つも出現しない** | 同上 |

4つすべてを満たすことを合格ラインとする。

### 4-3. 検証入力は誰が選ぶか

**課題文と固有語の選定は independent-verifier（作業した本人以外）が行い、選んだ文と語を evidence に残す。**
本人が選べると、自分の実装が通る文だけを選べてしまう（basis-reviewer 6回目 反証O-10）。
また、**同じ課題文を2回続けて検証に使わない**。

### 4-4. 課題の選び方（2組を必ず両方行う）

| 組 | 揃えるもの | 変えるもの | この組で落とすもの |
|---|---|---|---|
| 組1 | 期間・回数 | 会社名・業種・課題 | 完全な固定テンプレート |
| 組2 | **会社名・業種**・期間・回数 | **課題だけ** | 業種をキーにした固定表 |

組2 が要である。組1 だけだと「製造業ならこの12回、小売業ならこの12回」という業種ごとの
固定表を持つだけの実装が合格してしまう。

---

## 4-5. 開発チームの有無が効くこと（Q6が参照）

Q6 も 4-1 と同じ「出現」で測る。**骨格の比較は用いない。**

開発チームの有無だけを変えた2件を作り、「あり」の計画の見出し群には
**開発・実装・発注・受入に類する語が1つ以上出現し、「なし」の計画には出現しない**ことを確かめる。
判定に使う語の一覧は independent-verifier が選び、evidence に残す。

---

## 5. 判定の考え方

- **文字数の下限（15文字 / 20文字）** は、中身の無い値を機械的に弾くための下限であり、
  内容の良し悪しを測るものではない。
- **全ての回**が対象。1回でも欠けていれば Q5 は不合格。
- この一覧に無い要素の有無は Q5 の判定に影響しない。
